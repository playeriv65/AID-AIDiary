# AID Diary

[English](../../README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md) | **한국어**

Flutter로 만든 Windows·Android·Linux용 개인 일기 앱입니다.

최신 `main` 빌드는 [nightly 사전 릴리스](https://github.com/playeriv65/AID-AIDiary/releases/tag/nightly)에 있습니다(Android APK, Windows ZIP, Linux tar). 디버그 키로 서명되어 새로 설치할 수는 있지만, 릴리스 키로 서명된 설치본을 업데이트할 수는 없습니다.

## 화면

레이아웃은 일기 앱 Journey를 따릅니다. 휴대폰에서는 하단 바, 태블릿과 PC 창에서는 내비게이션 레일과 목록/상세 두 창입니다. 레이아웃과 기능만 참고했으며 코드, 리소스, 문구는 가져오지 않았습니다.

휴대폰, 태블릿, Windows 모두에서 검색은 스크롤되는 목록 위에 고정됩니다. 일기를 오래 훑어보면 작은 맨 위로 버튼이 나타납니다. 피드백은 「설정 > 도움말」에서 GitHub, 이메일, 텍스트 복사로 보낼 수 있습니다. Windows는 기본 제목 표시줄을 유지해 앱 아이콘과 AID Diary 이름을 보여 주고, 창 테두리 색을 앱 테마에 맞춥니다. [Windows 설정](../SETUP.md#windows-personal-installation)을 참고하세요.

- **일기**: 스토리 아래에 날짜별로 묶은 일기(시간, 제목, 미리보기, 기분, 장소, 날씨, 태그, 썸네일). 일기 날짜(오름차순·내림차순) 또는 마지막 수정 순으로 정렬합니다. 스토리는 오늘, 코치 프로그램의 그날 내용, 지난 오늘, 열린 타임캡슐, 아침 또는 저녁 질문, 빠른 체크인, 랜덤 산책, 이번 주와 올해 돌아보기입니다. 오늘, 코치의 날, 지난 오늘은 하나로 이어서 재생되며(통계, 30일 기분 차트, 그 자리에서 답하는 그날의 질문, 지난 오늘, 마무리 카드), 넓은 창에서는 카드로 표시됩니다.
- **첫 실행**: 「여기서 시작」 또는 「기존 기기에 연결」을 고릅니다. 읽기 전용 튜토리얼이 글쓰기, 미디어, 일기 찾기, 동기화, 개인정보를 소개하며 설정에서 다시 열 수 있습니다. 기존 기기가 연결을 승인하고, 새 기기가 일기를 받는 동안에도 계속 쓸 수 있습니다.
- **가까운 기기에서 이전과 기기 승인**: 이전 기기를 스캔하고 짧은 코드를 확인한 뒤, ID와 검증된 일기·미디어를 직접 전송합니다. 각 기기는 내보낼 수 없는 자체 서명 키를 만들며, 새 기기를 승인해도 이전 기기의 서명 키는 복사되지 않습니다. 네트워크 진단은 대기 중인 미디어를 설명하고 공식 서버의 실제 사용량을 보여 줍니다. 공식 미디어 요금제는 켜면 기본 월 1 GB이며, 직접 호스팅하면 기본적으로 용량 제한 없이 미디어를 영구 저장하고 관리자가 한도를 둘 수 있습니다.
- **모양과 손글씨**: 라이트와 다크 각각 독립된 색 구성, 줄·모눈·색지 종이, 직접 만든 식물·별·마스킹테이프 장식. 손글씨 캔버스는 Scribble과 perfect_freehand를 쓰며, 그림은 일반 PNG 첨부로 저장되고 스타일러스 전용 입력을 지원합니다.
- **기기 내 사진 제안**: 선택 사항. 기기에서 시간(원하면 장소도)별로 묶고, 스캔 범위는 제한되며, 직접 고른 경우에만 가져옵니다. 제안을 만들기 위해 원본 사진을 지우거나 업로드하지 않습니다.
- **랜덤 산책**: 지난 일기를 한 번에 하나씩 무작위로 보여 주며, 모두 볼 때까지 반복하지 않습니다. 전체, 사진이 있는 일기만, 좋은 날만 중에서 고릅니다.
- **돌아보기**: 한 주나 한 해를 스토리 슬라이드로. 개수, 기분(7일 한 줄 또는 1년 픽셀), 가장 많이 쓴 태그·장소, 사진, 월별 개수, 하이라이트.
- **빠른 체크인**: 기분과 한 줄을 두 번 탭으로 일기로 저장.
- **타임캡슐**: 일기를 특정 날짜까지 봉인합니다. 그때까지는 잠긴 상태로 표시되고 검색, 지난 오늘, 랜덤 산책, 미디어, 지도에 나오지 않습니다. 미리 열 수도 있습니다.
- **캘린더**: 일기 화면의 캘린더 버튼을 누르면 스크롤되는 달력이 그 자리에서 펼쳐지고, 날짜를 누르면 목록이 그날로 이동합니다. 캘린더 페이지(태블릿, `ui.navigate`)는 달력 옆에 선택한 날을 보여 줍니다.
- **미디어**: 첨부한 모든 사진, 동영상, 음성 메모.
- **지도**: 장소가 있는 일기를 OpenStreetMap 지도에 번호가 붙은 원으로 표시합니다. 일기가 여러 개인 지점을 열면 목록이 나옵니다. 두 손가락으로 확대·축소할 때 분명히 돌리지 않으면 지도가 회전하지 않고, 조금만 돌아간 지도는 북쪽으로 돌아옵니다.
- **댓글과 인용**: 이전 날짜의 일기에서 글을 선택하면 그 구절을 보관하거나 댓글을 달 수 있고, 일기 전체에 댓글을 달 수도 있습니다. 댓글은 답하는 내용을 인용한 오늘의 일기이며, 몇 줄로 쓰거나 전체 편집기로 펼칠 수 있습니다. 어떤 일기든 검색으로 찾은 다른 일기를 인용할 수 있고, 일기에는 그 일기에 답한 일기들이 표시됩니다. 보관한 구절은 한곳에 모입니다. 지난 일기를 편집하기 전에는 먼저 묻습니다(「다시 묻지 않기」 있음).
- **코치**: 기본 질문 프로그램과 템플릿, 그리고 내 템플릿. 프로그램에는 기간, 간격, 난이도가 표시되고, 참여하면 매일 또는 매주의 질문이 스토리에 나타나며(Android에서는 알림도) 답은 일기로 저장됩니다.
- **일기 보기**: 사진, 동영상, 음성 메모, 날짜 블록, 메타데이터, 본문. 별표, 그림으로 공유, 원본 미디어가 담긴 ZIP, 일반 텍스트 또는 HTML 페이지, 편집, 템플릿으로 저장, 타임캡슐로 봉인, 삭제. 이전/다음 일기.
- **편집기**: 위쪽에 일기 날짜(쓴 시각은 다른 날이었을 때만 표시), 오른쪽에 기분과 태그. 제목은 선택 사항(제목을 쓴 일기에만 제목이 있음). 본문. 「+」 타일로 갤러리나 파일의 사진·동영상, 카메라(Android), 음성 메모를 추가하고(사진의 날짜와 장소를 일기에 쓰도록 제안), 장소와 날씨 줄은 새 일기라면 자동으로 채워집니다. 날씨는 일기 날짜의 그 장소 날씨로, 조회하거나 직접 입력할 수 있고 같은 날 같은 장소의 일기가 함께 씁니다. 쓰는 동안 키보드 위에 막대가 나타나 템플릿과 Markdown 서식, 삽입 메뉴(체크리스트, 번호 목록, 표, 구분선, 코드 블록)를 제공하며 키보드를 닫으면 사라집니다. 변경 사항이 있을 때 뒤로 가면 저장할지 묻고, 완료 버튼은 저장합니다. 기본 템플릿에는 모닝 페이지와 저녁 돌아보기가 있습니다.
- **시간**: 일기는 쓴 곳의 그때 시각과 그곳의 UTC 오프셋을 저장하므로, 다른 시간대로 날아가도 아무것도 바뀌지 않습니다. 다른 시간대에서 쓴 일기에는 시간대가 표시됩니다(예: UTC+8). Journey와 Day One 가져오기·내보내기는 일기마다 자기 시간대로 변환합니다. 모든 일기는 쓴 시각과 속한 일기 날짜를 모두 저장합니다. 날짜별로 세는 모든 것(일기 목록, 캘린더, 연속 기록, 돌아보기, 통계, 알림, 위젯)은 일기 날짜를 쓰며, 일기 날짜는 쓴 시각을 건드리지 않고 편집기에서 언제든 바꿀 수 있습니다. 4:00 전에 쓴 새 일기는 전날로 셈하고(작은 달 표시), 4:00에서 6:00 사이에는 편집기가 어느 날인지 묻고(답하기 전까지는 오늘), 그 이후는 그날로 셉니다. 두 시각 모두 설정에서 바꿀 수 있고 새 일기에만 적용됩니다. 지난 날에 대해 나중에 쓴 일기는 쓴 시각을 보여 줍니다.
- **언어**: 기본적으로 시스템을 따르며, 「일반」 설정의 「앱 언어」 하나로 바로 바꿀 수 있습니다.
- **기분**: 편집기의 기분 버튼 바로 아래에 다섯 가지 기분과 명시적인 지우기 동작. 고르면 확인 없이 바로 적용됩니다.
- **장소**: 현재 위치를 바로 쓰고, 이름을 바꾸거나 지울 수 있습니다. 선택기에서는 사용자 지정 이름, 저장한(별표) 장소, 장소 검색, 주변 장소, 최근 장소를 쓸 수 있습니다.
- **검색**: 제목과 본문 검색에 인라인 태그·별표·기분 필터.
- **통계**: 연속 기록, 기분 추이, 「무엇이 나를 이렇게 느끼게 하나」(어떤 기분과 가장 자주 함께 나오는 태그), Year in Pixels.
- **최근 삭제**: 삭제한 일기는 30일(설정 가능) 뒤에 완전히 지워집니다. 복원하거나 미리 지울 수 있습니다.
- **동기화**(선택): 내 Google Drive(앱은 자기 `AID Diary` 폴더만 볼 수 있음), 원하는 WebDAV 서버(Nextcloud, Synology, 坚果云 등) 또는 `server/`의 AID 동기화 서버를 통해 모든 기기에서 일기, 사진, 태그, 템플릿을 같게 유지합니다. 항상 종단 간 암호화되며 일기용 계정이나 비밀번호가 없습니다. 각 기기가 사용자의 키를 가지며, 새 기기는 이미 설정된 기기와 페어링해 키를 받고(한쪽에 코드를 표시하고 다른 쪽에서 입력하거나 스캔), 모든 기기를 잃어버리면 복구 코드(무작위 또는 직접 정한 것)로 되찾습니다. 저장소에는 암호문만 있습니다. 가까운 신뢰 기기끼리는 데이터를 직접 주고받습니다. AID 호환 WebDAV 계정과 새 네트워크 서비스가 있으면 기기들은 공용 IPv4/IPv6 경로도 찾고, WebRTC/STUN을 시도하며, 필요하면 한도가 있는 실시간 중계를 씁니다. Google Drive와 일반 WebDAV는 LAN과 저장소만 씁니다. 일기 본문이 먼저 동기화되고, 검증된 미디어 조각은 허용량 안에서 경로를 바꿔 이어서 전송됩니다. 상태는 「일기 동기화됨」, 「일부 미디어 전송 중」, 「다른 기기를 기다리는 중」을 구분합니다. 실시간 중계는 두 기기가 모두 온라인이어야 하지만 별도의 임시 미디어 캐시는 그렇지 않으며, 둘 다 백업은 아닙니다. 수정 사항은 몇 초 뒤, 앱이 열려 있는 동안 동기화됩니다. 두 기기가 같은 일기를 바꾸면 더 새로운 쪽이 이기고 다른 쪽은 「최근 삭제」에 남습니다. 동기화에 실패한 일기에만 작은 빗금 구름 표시가 붙습니다. 네트워크 경로와 검증 현황: [docs/SYNC_NETWORK.md](../SYNC_NETWORK.md).
- **기기와 동기화 세부 정보**: 각 기기는 처음에 모델명이나 컴퓨터 이름을 쓰며 이름을 바꿀 수 있습니다. 페어링하면 신뢰 기기 자동 검색이 시작되고, 평소 상태 표시는 단순하게 유지됩니다. 동기화 세부 정보를 열면 이름이 붙은 전체/부분 사본과 다른 기기가 마지막으로 내용을 확인한 시각을 볼 수 있습니다. 임시 클라우드 캐시는 따로 표시되고, 네트워크와 키 세부 정보는 추가 옵션 안에 있습니다.
- **내보내기**: JSON(모든 일기와 제목, 장소, 날씨, 태그, 첨부 파일 이름. JSON 가져오기로 다시 읽을 수 있음), Markdown, Journey와 Day One이 가져올 수 있는 아카이브, 그리고 전체 백업.
- **가져오기**: [One Diary(一本日记) v3 백업](../ONE_DIARY_IMPORT.md)(원래 일기 날짜, 숨김 표시, 기기 내 첨부 유지), Journey 백업(두 형식 모두)과 Day One JSON 내보내기(사진, 태그, 별표, 장소, 날씨 포함, 활동은 태그로), 그리고 Daybook, Daylio, Diarium, Diaro, My Brain, OneShot, Pixels.
- **숨긴 일기**: 「설정 → 보안」에 있는, 기기 인증 후 여는 영역으로 일반 목록, 검색, 위젯, 내보내기, CLI 내용에서 제외됩니다. 숨김은 화면상의 일일 뿐이어서 숨긴 일기도 동기화되며 모든 기기에서 숨겨진 채로 유지됩니다. 전체 백업에는 다른 일기와 똑같이 포함됩니다. [정확한 범위](../ARCHITECTURE.md#hidden-entries)를 참고하세요.
- **태그**: 새 일기장에는 태그가 없습니다. 태그는 끌어서 정한 순서(선택기에서 길게 누르기)를 유지하고, 일기 카드에 태그 이름이 표시되며, 가져오기로 들어온 태그는 사용 횟수 순으로 정렬됩니다.
- **사진**: 기본적으로 받은 그대로 저장합니다. 새 사진을 약 1 MB의 WebP로 저장하거나, 저장된 사진을 한 번에 압축할 수도 있습니다(되돌릴 수 없음).
- **설정**: 일반(테마, 배경, 본문 글꼴·크기·줄 간격, 단위, 12/24시간제, 새 일기의 일기 날짜를 정하는 시각, 장소와 날씨 자동 추가), 데이터와 저장소(백업, 내보내기, 최근 삭제), 스토리(아침과 저녁 질문, 지난 오늘), 알림(Android: 요일별 알림, 지난 오늘, 며칠 쓰지 않았을 때의 알림, 상시 빠른 기록 알림), 보안, 도움말(자주 묻는 질문, 개인정보), 정보.
- **명령줄과 에이전트**: 모든 기능은 하나의 액션이고, 앱의 버튼, 명령 팔레트(Windows에서 Ctrl+K, 「설정 → 명령줄 → 모든 명령」), `aid` 명령줄이 모두 같은 것을 실행하므로 스크립트나 AI 에이전트가 하는 일이 그대로 앱에 나타납니다. 릴리스 빌드에서는 「설정 → 명령줄」을 켜기 전까지 꺼져 있으며, API는 이 기기에서만 수신하고 시작할 때마다 새 토큰을 씁니다.
- **Android 홈 화면 위젯**: 오늘 상태, 매일의 일기 사진, 연속 기록, 매일의 글쓰기 질문, 빠른 기분. 질문이나 기분을 누르면 조용히 일기를 저장하는 대신 편집할 수 있는 초안이 열립니다.

일기, 사진, 좌표는 동기화를 켜지 않는 한 기기에 남고, 켜면 선택한 저장소와 신뢰 기기로 암호화되어 전달됩니다. 네트워크 사용은 모두 선택 사항이며 [assets/config/app_config.json](../../assets/config/app_config.json)에서 설정합니다.

- OpenStreetMap 지도 타일과 Nominatim 장소 이름·장소 검색.
- 현재 위치 근처의 이름 있는 장소를 찾는 Overpass(OpenStreetMap). 위치가 있는 상태로 장소 선택기를 열 때만.
- Open-Meteo 날씨(최근 날짜는 예보, 오래된 일기는 기록 자료). 좌표와 날짜만 보냅니다.
- Google 로그인과 Drive API. Google Drive로 동기화할 때만([docs/GOOGLE_DRIVE.md](../GOOGLE_DRIVE.md)).
- 동기화를 켰을 때의 신뢰 기기 검색과 암호화된 동기화 전송: LAN DNS-SD, 그리고 AID 호환 WebDAV 네트워크 서비스의 경우 인증된 시그널링, 공용 직접 연결 확인, 설정한 STUN, 한도가 있는 실시간 중계. 앱은 TURN 서비스를 제공하지 않습니다.

저장소와 알림 외의 Android 권한: 위치(장소. 새 일기나 지도를 열 때 요청)와 마이크(음성 메모). 둘 다 그 기능을 쓸 때만 요청합니다.

## 언어

화면은 기본적으로 시스템 언어 설정을 따르며, 설정에서 바꿀 수 있습니다. Flutter 공식 현지화 방식으로 번역을 앱에 포함해 오프라인에서도 씁니다. 35개 로캘 모두 영어 메시지 템플릿을 다 담고 있으며, 카탈로그 테스트가 빠지거나 빈 메시지와 동적 인수를 확인합니다. 번역이 다 있다고 해서 원어민 검토를 거쳤다는 뜻은 아닙니다. 대응 규칙, 번역 관리와 검증은 [국제화](../ARCHITECTURE.md#internationalization)를 참고하세요.

## 개발

주 개발 환경은 Windows입니다(WSL도, SDK 서브모듈도 쓰지 않습니다). [문서 색인](../INDEX.md)과 [유지보수 인수인계](../HANDOFF.md)에서 시작하세요. 설정, 아키텍처, 제품 결정, 테스트, 각 하위 시스템에 관한 질문을 담당 가이드로 안내하고 가장 최근의 날짜가 붙은 체크포인트를 알려 줍니다. [엔지니어링 원칙](../ENGINEERING.md)은 Flutter/Google 지침을 어떻게 받아들이는지, 변경을 어떻게 검토하고 문서를 어떻게 관리하는지 설명합니다. [설정](../SETUP.md)은 새 컴퓨터, 로컬 도구 체인 구성, 서명, 테스트 기기를 다룹니다.

```powershell
./scripts/dev.ps1 pub          # 새로 체크아웃한 뒤 앱과 CLI 의존성 해결
./scripts/dev.ps1 l10n         # ARB를 바꾼 뒤 현지화 소스 재생성
./scripts/dev.ps1 test -TestFiles test/sync/local_device_test.dart # 영향받는 파일/디렉터리
./scripts/dev.ps1 test-all     # 의도적인 전체 오프라인 회귀 테스트
./scripts/dev.ps1 analyze      # 정적 분석
./scripts/dev.ps1 screenshots  # 창 없이 artifacts/ui-*.png 재생성
./scripts/dev.ps1 windows      # Windows 앱 실행
./scripts/dev.ps1 windows-build # 창을 열지 않고 Windows 빌드
./scripts/dev.ps1 windows-stage # 그 번들을 고정된 DEV_WINDOWS_RUNTIME에 배치(실행하지 않음)
./scripts/dev.ps1 windows-profile-build # 분리된 Windows 성능 빌드
./scripts/dev.ps1 windows-profile-stage # profile 번들을 같은 고정 경로에 배치
./scripts/windows_scroll.ps1 -Label current # 스크롤바 이동과 프레임 타임라인 검증
./scripts/windows_scroll.ps1 -Label wheel -WheelOnly # 마우스 휠 애니메이션과 프레임 간격
./scripts/dev.ps1 android      # 에뮬레이터에서 실행
./scripts/dev.ps1 apk          # 디버그 APK(dev 플레이버) 빌드
./scripts/dev.ps1 profile -Device <serial>     # dev 앱을 profile 모드로 설치
./scripts/dev.ps1 frame-rate -Device <serial>  # 일기 4000개로 그 프레임 속도 측정
./scripts/dev.ps1 frame-rate -Device windows   # 같은 측정을 이 컴퓨터에서, 숨긴 창과 임시 데이터로
./scripts/dev.ps1 release      # 서명된 릴리스 APK를 빌드해 연결된 기기에 설치
./scripts/dev.ps1 cli          # aid 명령줄을 build\cli\aid.exe로 빌드
```

`aid`는 실행 중인 앱과 이 컴퓨터에서 또는 adb를 통해 통신합니다(필요하면 그쪽에서 dev 플레이버를 시작합니다).

```powershell
aid actions                          # 모든 액션과 인수
aid guide                            # 같은 내용을 에이전트용 가이드로
aid entry.list limit=5
aid -d <adb serial> entry.seed count=4000
aid -d <adb serial> sync.now
aid sync.network                      # 경로, 선택된 ICE 쌍, 예산
aid sync.network_paths paths=ice,cache stunOnly=true  # 개발 빌드 전용
aid entry.delete id=12 --yes         # 파괴적인 액션에는 --yes 필요
```

Android 빌드는 JDK 23에서 실행됩니다. 많은 플러그인이 Kotlin JVM 타깃을 지정하지 않기 때문에, 루트 `android/build.gradle`이 각 모듈의 Kotlin에 그 모듈의 Java가 쓰는 것과 같은 JVM 타깃을 줍니다. Flutter의 Android SDK 경로는 `flutter config --android-sdk`로 고정합니다.

프로젝트 전체의 [테스트 정책](../TESTING.md)은 Flutter, Go, CLI, 네이티브 플랫폼에 대해 변경과 테스트의 대응표, 전체 회귀와 릴리스 관문, 핵심 사용 흐름, 결과 보고를 정합니다. 독립된 순수 로직은 범위를 좁힌 단위 테스트로 충분하지만, UI, 영속성, 네이티브 동작은 각자 담당하는 계층의 테스트가 필요합니다. 전체 회귀는 범위가 넓거나 위험이 큰 변경, 릴리스 관문, 그리고 작업한 날의 마무리 안전망으로 한 번 돌리며, 테스트한 뒤 바뀌지 않은 상태에는 기존 결과를 다시 씁니다. 계층별 타깃(`test-unit`, `test-widget`, `test-integration`)도 `-TestFiles`를 받으며, 외부 서비스에는 명시적인 `test-live`가 필요합니다. GitHub Actions는 `main`에 대한 모든 push를 검사하고 nightly 빌드를 패키징합니다([지속적 통합](../TESTING.md#continuous-integration)).

스크린샷은 `tool/screenshots/`의 위젯 테스트가 실제 글꼴(Flutter SDK 아이콘, Windows의 Noto Sans SC와 Segoe Emoji)로 렌더링하며 창은 열리지 않습니다. `-TestFiles`를 넘겨 영향받는 스크린샷 파일만 렌더링하고 이미지를 확인하세요. 이 스크립트들은 골든 이미지를 자동으로 비교하지 않습니다.

플랫폼: Windows, Android, Linux(nightly 패키지 제공. Linux에서는 아직 동영상과 음성 메모를 재생할 수 없고, 숨긴 일기에는 앱 비밀번호가 필요합니다). iOS와 macOS는 나중에 지원하며, 웹은 구성되어 있지 않습니다.
